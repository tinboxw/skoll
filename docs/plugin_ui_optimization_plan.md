# 插件与 UI 优化实施计划

> 日期: 2026-06-06
> 范围: 已实现功能复盘、未实现功能规划、插件管理 UI 首批落地

## 1. 已实现功能复盘

### 1.1 需要继续优化的功能

| 模块 | 当前状态 | 问题 | 优化方向 |
|------|----------|------|----------|
| 插件管理页 | 功能完整，支持同步、安装、启停、卸载、配置、日志、调试、默认首页、Tab 固定 | 操作密度过高，危险动作和普通动作混排，表格横向压力大 | 改为状态卡片 + 分区表格 + 操作下拉 + 右侧检查器 |
| 插件 UI 集成 | 支持集成模式与 standalone 模式，支持 iframe 页面 | 缺少插件运行态健康、加载失败、权限缺失、版本兼容的统一视觉表达 | 增加插件状态模型和统一空态/错误态组件 |
| DevPortal 发布链路 | 后端 API 已覆盖脚手架、验证、打包、审批、灰度、回滚 | 前端还不是完整工作台，更像管理表单集合 | 建成发布流水线视图：草稿、校验、打包、审批、灰度、回滚 |
| 灰度/回滚 | 后端已有三策略和回滚点 | UI 缺少策略配置器、进度可视化、风险提示 | 增加灰度策略表单、发布进度、回滚点列表和确认流程 |
| 前端工程 | Vue/Router/Pinia 已稳定 | Vite 2.9 偏旧，未接入组件库，样式分散 | 升级 Vite 5，接入 Element Plus，并逐页迁移 |
| 通用组件 | 有 Table/Dialog/Form 等轻量组件 | 与 Element Plus 重叠，维护价值变低 | 保留业务封装，底层改用 Element Plus |
| 文档 | 核心架构/API/配置文档已有 | 缺少当前质量基线和 UI/插件实施路线 | 用本文件承接插件 + UI 的近期计划 |

### 1.2 不合理或需要纠偏的地方

| 问题 | 判断 | 处理方式 |
|------|------|----------|
| 先大规模迁移 Element Plus | 不合理。一次性替换 6 个页面会扩大回归面 | 先升级构建链，再从插件页和 Common 组件开始 |
| M7 写部署 100% 又包含性能基线 | 表述不清。部署配置完成不等于测试质量完成 | 部署归 M7，覆盖率/性能/CI 归 M15 |
| 插件管理页所有动作平铺 | 不合理。高频动作、低频动作、危险动作没有分层 | 高频按钮外露，配置/日志/卸载进入下拉菜单 |
| 全量注册 Element Plus | 短期可用但包体不合理 | 改为 `unplugin-auto-import` + `unplugin-vue-components` 按需导入 |
| `xlsx` 存在高危审计项且无修复版本 | 有安全风险，尤其涉及用户上传表格解析 | 后续评估替换为维护状态更好的解析库，或限制导入入口、文件大小和解析范围 |
| 插件能力继续扩张优先 | 暂不合理。当前更缺 UI 工作台和质量基线 | 先做插件发布/灰度/回滚 UI，再扩展市场/策略引擎 |

## 3. 本轮已开始实现

- 升级 `vite` 至 5.x，升级 `@vitejs/plugin-vue` 与 TypeScript。
- 引入 Element Plus，并通过按需导入降低包体。
- 重构插件管理页为更清晰的运营控制台结构。
- 增加 Vite manual chunks，将 Vue 和 xlsx 独立分包。
- 将前端路由改为懒加载，降低首屏业务包体。
- 将 Common Table/Dialog/Form 改为 Element Plus 轻量封装。
- 在插件管理页新增 DevPortal 工作台首版：脚手架、项目列表、全量校验、打包、流水线、发布单创建/审批/拒绝/执行、发布/灰度任务列表、percent 灰度和比例回滚。

验证命令:

```bash
cd web
npm run build
```

当前结果: 构建通过，页面路由已按需切分，未出现大 chunk 警告。

## 4. 下一步实现顺序

1. 为插件 iframe 页面增加统一运行态：加载中、降级、无权限、加载失败。
2. DevPortal 工作台继续补齐：回滚历史、表单校验、任务自动轮询、审批/执行二次确认。
3. 将 User/Role/Permission/Setting 页面逐步迁移到 Element Plus。
4. 替换或隔离 `xlsx`，解决导入链路的高危审计项。
5. 执行 `go test ./...`、前端 smoke、覆盖率统计，形成 M15 基线报告。
