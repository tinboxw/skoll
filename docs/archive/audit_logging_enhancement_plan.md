# 审计与日志增强实施方案

更新时间：2026-05-10
状态：S4 设计基线（可执行）

## 1. 目标

- 建立统一审计与日志体系。
- 支持检索、导出、告警与可视化。
- 满足安全合规与留痕要求。

## 2. 审计覆盖范围

- 用户身份行为：登录、登出、密码变更、会话异常。
- 权限行为：角色变更、权限授予/撤销、越权访问。
- 配置行为：系统设置、插件配置、开关操作。
- 数据行为：新增、修改、删除、批量导入导出。

## 3. 审计日志字段标准

- event_id
- operator_id
- operator_account
- operator_role
- action_type
- resource_type
- resource_id
- before_json
- after_json
- result
- error_code
- error_message
- request_id
- trace_id
- client_ip
- user_agent
- occurred_at

## 4. 存储与生命周期

- 热数据：7-30 天，在线检索。
- 温数据：30-180 天，归档库。
- 冷数据：180 天以上，对象存储压缩归档。
- 敏感字段脱敏与访问分级控制。

## 5. 查询与导出

能力：
- 多条件筛选（人、时间、模块、结果、IP）。
- 高风险模板查询（失败登录、批量删除、权限变更）。
- 异步导出 CSV/Excel，导出任务可追踪。

## 6. 异常行为监控

规则建议：
- 短时多次登录失败。
- 非工作时段高危操作。
- 批量删除/导出阈值触发。
- IP 异常漂移。
- 连续越权拒绝。

告警建议：
- 邮件、IM、Webhook。
- 告警分级（P1/P2/P3）与自动抑制。

## 7. 可视化

- 总览看板：操作趋势、失败率、风险分布。
- 事件时间线：按 trace_id 聚合。
- 模块热力图：高频高风险操作区域。

## 8. 安全与合规

- 审计日志追加写，防篡改。
- 审计访问行为本身也被审计。
- 导出行为需权限与二次确认。

## 9. S4 完成标准

- 核心操作全覆盖审计。
- 查询、导出、告警、可视化四项能力可用。
- 留存策略与脱敏策略可配置并生效。
