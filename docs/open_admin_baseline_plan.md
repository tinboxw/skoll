# Skoll 开源 Admin 基线计划

> 最后更新: 2026-06-06
> 目标: 以 go-admin 的工程分层为主线，参考 hisiphp 的插件/模块化经验，以及 Gin-Vue-Admin 的后台能力完整度，形成适合 Skoll 的开源管理平台路线。

---

## 1. 当前判断

Skoll 已具备后端分层、RBAC、审计、插件生命周期、DevPortal、灰度/回滚和基础前端后台框架。当前不适合继续堆孤立页面，主要工作应转向“可扩展后台基建”：

- 菜单、路由、按钮权限、API 权限需要同源建模。
- 插件能力需要从“能安装/发布”升级为“能声明 UI、菜单、权限、配置、资产和发布策略”。
- UI 需要从自定义样式过渡到稳定组件体系，并补齐后台产品常见交互。
- 配置、字典、文件、代码生成、组织/部门等通用能力需要进入主线。
- 测试、CI、OpenAPI、文档需要成为开源项目的可信入口。

## 3. 缺失的核心功能

### P0: 后台基建优先补齐

| 功能 | 说明 | 价值 |
|------|------|------|
| 动态菜单/动态路由 | 菜单树、排序、图标、可见性、插件菜单合并 | go-admin 类项目的后台骨架入口 |
| 前端权限工具 | 菜单权限、按钮权限、页面权限统一判断 | 避免每个页面手写权限判断 |
| 组织/部门/岗位 | 部门树、岗位、用户组织归属 | 支撑数据权限和真实后台管理 |
| 字典管理 | 字典类型、字典项、状态、排序 | 支撑表单选项、业务枚举、插件配置 |
| 参数配置管理增强 | 系统参数、运行时配置、缓存刷新 | 与 hisiphp/GVA 类项目能力对齐 |
| 文件/附件管理 | 上传、存储驱动、本地/对象存储抽象 | 用户头像、插件资产、业务附件基础 |

### P1: 插件与 UI 主线

| 功能 | 说明 | 价值 |
|------|------|------|
| 插件 manifest UI schema | 插件声明菜单、配置表单、权限、导航位置；`ui_menu` / `config_schema` 首版已落地 | 插件不只是一段后端能力，而能自描述 UI |
| 插件市场/仓库视图 | 本地插件、远端仓库、版本、签名、风险 | 开源生态入口 |
| 插件权限申请/审批 | 插件安装时展示权限、风险、资源访问 | 降低插件扩展风险 |
| UI 配置化表单 | 已新增 `SchemaForm`，并基于 manifest `config_schema` 渲染插件配置，系统设置页也已复用常用配置 schema | 减少重复页面开发 |
| Element Plus 全量迁移 | User/Role/Permission/Audit/Setting 统一交互 | 提升开源项目第一眼质量 |

### P2: 成熟后台能力

| 功能 | 说明 | 价值 |
|------|------|------|
| 代码生成器 | 基于表结构/模型生成 CRUD、API、前端页面 | 借鉴 GVA/go-admin 的效率优势 |
| 通知公告 | 站内信、公告、系统通知 | 管理后台常见能力 |
| 工作流/审批 | 简化审批流、任务、状态流转 | 可服务插件发布、业务审批 |
| 多租户/数据范围 | 租户、部门、本人、自定义数据权限 | 企业后台关键能力 |
| OpenAPI/SDK 生成 | API 文档、客户端生成、接口契约校验 | 开源协作与二次开发友好 |

## 4. 下一步计划

| 顺序 | 工作项 | 产出 | 验收 |
|------|--------|------|------|
| 1 | 菜单注册中心前端基线 | `web/src/navigation/menu.ts`，系统/插件菜单统一排序和权限过滤 | `npm run build` 通过，侧栏行为不回退 |
| 2 | 菜单/权限后端模型设计 | 菜单表、权限点、插件菜单声明映射草案 | 文档和 migration 草案完成 |
| 3 | Element Plus 迁移第二批 | User/Role/Permission/Audit/Setting 页面迁移 | 列表、搜索、表单、批量操作体验统一 |
| 4 | 字典与配置 schema | 字典管理 API/UI、配置 schema 约定 | 插件配置页可复用 schema 表单 |
| 5 | 插件 manifest 扩展 | 菜单、权限、配置 schema、资产声明 | 插件安装后自动进入菜单/权限体系 |
| 6 | 文件管理基础 | 上传 API、存储驱动接口、前端上传控件 | 支持头像、附件、插件资产上传 |
| 7 | 质量门禁 | 前端 build/typecheck、Go 覆盖率、OpenAPI/manifest 校验 | CI 能稳定暴露回归 |

## 5. 本轮已开始实现

- 已新增前端菜单注册入口 `web/src/navigation/menu.ts`。
- 已将系统菜单、插件侧栏菜单、角色/权限过滤从 `App.vue` 抽离。
- 已为前端插件 manifest 增加 `uiMenu` 类型，并为 `docs/schemas/plugin-manifest.schema.json` 增加 `ui_menu` 声明。
- 已补齐后端 manifest `ui_menu` 解析、校验、签名 canonical 覆盖和 `/v1/plugins` 输出映射。
- 已新增前端 `canAccess` 权限工具与 `v-permission` 指令，并在插件管理页、User 列表、User 表单页、Role 列表和角色编辑页首批接入按钮级权限。
- 已抽出前端共享权限目录 `web/src/permissions/catalog.ts`，权限矩阵页和角色编辑页开始共用同一套权限点。
- 已将权限管理页升级为 Element Plus 权限矩阵，支持按角色授予/撤销权限，并保留 RBAC policy 与权限校验面板。
- 已新增后端 `/v1/system/menus` 菜单树 API，默认返回系统菜单，并可通过系统设置持久化覆盖。
- 已新增前端 navigation store，认证后加载 `/v1/system/menus`，侧栏优先使用远端菜单，再合并插件 `ui_menu` 并统一权限过滤。
- 已新增菜单管理页首版，支持树形菜单编辑、显隐、同级上移/下移排序、角色/权限字段和保存。
- 已为静态后台页面补齐页面级路由权限，并将路由守卫统一到 `canAccess` 与隐含权限规则。
- 已让插件前端路由继承 `ui_menu.required_roles/required_permissions`，并修正默认页无权访问时的回退逻辑。
- 后续可在该入口继续接入 Element Plus 交互细节优化、独立 `ui_route` 声明和可选拖拽排序。
