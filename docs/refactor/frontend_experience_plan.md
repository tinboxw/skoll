# Skoll 前端体验与工程专项计划

> 当前状态: 前端专项计划  
> 更新时间: 2026-06-18  
> 目标: 将 Skoll 前端建设成优秀、漂亮、稳定、高性能、可长期扩展的开源 Admin 控制台。

## 1. 结论

当前重构计划包含前端，但前端任务主要分散在 M1-M7 的功能交付中。为了达到更高的体验、视觉、性能和工程质量目标，需要增加独立前端专项主线。

前端目标不是“页面能用”，而是:

- 操作体验优秀: 高频后台操作顺手、少跳转、低打扰。
- 视觉质量优秀: 专业、克制、清晰、统一，不像临时拼装页面。
- 状态完整优秀: 加载、空态、错误、无权限、保存中、成功、失败、确认都有设计。
- 性能优秀: 路由懒加载、表格稳定、请求克制、重渲染少。
- 工程优秀: Vue 3 + TypeScript + Pinia + Element Plus 结构清晰，可生成、可测试、可扩展。

## 2. 前端原则

1. Skoll 是 Admin 框架，不做营销页式 UI。
2. 页面是工作台，不是展示页；优先表格、筛选、抽屉、弹窗、状态标签、批量动作。
3. 所有前端页面必须权限感知。
4. 所有异步页面必须有加载、空态、错误态。
5. 所有危险操作必须有确认。
6. 所有页面必须支持窄屏基本可用，不允许文字重叠和按钮溢出。
7. 不做旧页面路径、旧状态字段、旧 store 的兼容方案。

## 5. 体验验收标准

每个可见页面至少满足:

| 维度 | 验收要求 |
|---|---|
| 信息架构 | 标题、主要动作、筛选、列表、详情入口清楚 |
| 视觉统一 | 间距、字号、按钮、标签、表格、表单与同类页面一致 |
| 状态完整 | loading、empty、error、no permission、saving、success、failed |
| 权限感知 | 路由、菜单、按钮、接口失败均能一致反馈 |
| 表格体验 | 列稳定、状态可扫、操作紧凑、批量动作清晰 |
| 表单体验 | 校验及时、错误明确、保存状态可见 |
| 危险操作 | 二次确认、影响范围明确、失败可恢复 |
| 响应式 | 窄屏无文字重叠、按钮溢出、内容遮挡 |
| 性能 | 不因加载大表、插件详情、开发者门户造成明显卡顿 |

## 6. 前端性能预算

初始预算先作为执行约束，M0/FE0 后用真实测量替换:

| 项目 | 初始目标 |
|---|---|
| 路由加载 | 主要业务页面按路由懒加载 |
| 首屏 | Admin shell 尽快可交互，重页面延迟加载 |
| 表格 | 默认服务端分页；大列表不得一次性渲染全部 |
| 请求 | 菜单、权限、字典等共享数据缓存并显式失效 |
| 插件页 | 插件详情、发布任务、日志、风险报告按需加载 |
| 构建 | 每次明显增加依赖或 chunk 体积必须记录原因 |

## 7. 前端验收流程

每个前端 Work Item 通过前至少执行:

```powershell
cd web
npm run build
```

如果存在 `typecheck`:

```powershell
cd web
npm run typecheck
```

可见 UI 改动还必须浏览器验收:

1. 打开受影响页面。
2. 检查正常数据、空态、错误态、无权限态。
3. 检查保存、删除、批量操作和确认弹窗。
4. 检查窄屏宽度。
5. 在 `acceptance_log.md` 记录结果。

## 8. 与主任务关系

前端专项不是替代 M1-M7，而是提供横向质量门槛:

- M1 权限/菜单完成时，FE1-FE3 的权限态和菜单体验必须同步验收。
- M2 审计完成时，FE3 的审计页体验和 FE5 的 smoke 必须同步验收。
- M3 文件完成时，FE3 的上传/下载/进度/错误态必须同步验收。
- M5 生成器完成时，生成出来的页面必须满足 FE1-FE6 标准。
- M6 插件市场完成时，插件生命周期页面必须满足 FE4 标准。
