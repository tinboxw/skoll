# FE1 Skoll Admin Visual Principles

日期: 2026-06-19  
范围: FE1-01  
状态: Accepted baseline

## 目标

Skoll Admin 是面向日常运维、权限治理、插件管理和审计排查的开源后台框架。视觉系统必须服务于高频操作、快速扫描和低干扰判断，而不是展示型首页或营销型产品介绍。

本原则作为 FE1 后续布局、表格、表单、状态组件、样式变量和响应式任务的上层约束。

## 核心原则

| 原则 | 要求 | 不接受 |
|---|---|---|
| Professional | 页面像生产后台工具，信息结构清楚，操作优先级稳定。 | 以品牌展示、口号、装饰视觉替代真实数据和控件。 |
| Restrained | 色彩、阴影、圆角和动效克制，只用于区分状态、层级和当前上下文。 | 大面积渐变、漂浮装饰、过强阴影、无语义的视觉强调。 |
| Scannable | 标题、筛选、表格、状态标签、行操作保持固定位置和稳定密度。 | 大卡片堆叠、重复说明文案、字段在不同页面随机换位。 |
| Plugin-first | 系统页面和插件页面共享外壳、导航、状态、权限和风险表达。 | 插件页面自成一套视觉语言，或把插件能力藏在二级说明中。 |
| Operational | 所有视觉判断都要支持重复使用: 查询、编辑、保存、确认、失败恢复。 | 只为截图好看，缺少 loading、empty、error、no-permission 等真实状态。 |
| No compatibility styling | 新规范直接服务当前架构，不保留旧页面路径或旧组件外观的兼容层。 | 为旧页面单独维护一套视觉变量、旧按钮样式或旧布局分支。 |

## 当前样式锚点

现有前端已经具备可延续的视觉基础:

- `web/src/styles/variables.scss`: 浅灰应用背景、白色 surface、深色正文、青绿色主色、风险/成功/警告状态色、深色侧栏色。
- `web/src/styles/global.scss`: 全局字体使用 IBM Plex Sans、Segoe UI、PingFang SC，表单控件继承字体。
- `web/src/components/Layout/MainContent.vue`: 主内容使用白色 surface、边框、轻阴影和 16px 内边距。
- `web/src/components/Layout/Sidebar.vue`: 深色侧栏、图标导航、当前项高亮。
- `web/src/components/Layout/Header.vue`: 标题、同步状态、插件数量、语言切换和用户操作在同一顶部工作区内。

后续 FE1 任务可以调整这些锚点，但必须保持专业、克制、可扫和插件优先的方向。

## 视觉判断规则

### 色彩

- 背景使用 `--color-bg`，承载内容使用 `--color-surface` 或 `--color-surface-soft`。
- 主操作使用 `--color-primary`，悬停或强调使用 `--color-primary-strong`。
- 状态色只用于状态和风险: success、warning、danger 不用于装饰。
- 插件风险、权限风险、审计风险需要共享同一风险表达，不允许每页自定义一套颜色语义。
- 页面背景可以有轻微层次，但不得用营销式大面积渐变或装饰性光斑抢占注意力。

### 密度与间距

- 后台页面默认紧凑但不拥挤: 页面外壳、标题区、筛选区、表格区之间保持清晰分隔。
- 常用操作靠近数据上下文，批量操作靠近选择状态，危险操作靠确认流程保护。
- 卡片只用于单个重复对象、弹窗或明确的工具容器；页面 section 不堆叠成多层卡片。
- 不使用嵌套卡片表现层级，优先使用标题、边框、分隔线、表格列和抽屉结构。

### 字体与文案

- 页面标题保持工具级尺寸，不使用 hero 级展示字。
- 表格、筛选、状态、行操作使用稳定字号，避免因页面不同而跳动。
- 可视文案只表达数据、状态或操作，不写功能说明式占位文本。
- 中英文环境都必须避免按钮文本溢出；长错误、trace、token 使用截断、换行或详情区。

### 形状与层级

- 圆角使用现有变量族，后台常规控件保持 8px 到 12px 的克制范围。
- 阴影只用于浮层、抽屉、菜单、顶部区或真正需要抬升的容器。
- 表格、抽屉、弹窗、菜单的层级优先用 Element Plus 的语义组件表达。
- 图标用于导航和工具操作，按钮内图标优先使用 lucide 或现有组件库图标。

### 状态与反馈

- 每个核心页面必须具备 normal、loading、empty、error、no-permission、saving、success、danger confirmation 状态。
- 状态组件要占据原数据区域，不把用户带到营销式空页面。
- 保存、导出、启停、删除、回滚、安装插件等操作必须有进行中和失败反馈。
- 后续浏览器验收要记录窄屏、权限受限、后端错误和危险动作确认。

### 插件优先

- 插件入口、插件页签、插件详情、插件风险、插件权限 diff 和插件生命周期动作使用后台同一视觉系统。
- 插件页面可以承载远端 UI，但宿主外壳必须保持 Skoll 的导航、同步状态、权限和风险语义。
- 插件能力必须作为一等工作流出现，不能只藏在设置项或说明文档中。

## FE1-01 验收结论

- Professional: Passed，原则明确后台工具感和生产使用场景。
- Restrained: Passed，原则限制装饰性渐变、过强阴影、无语义强调和嵌套卡片。
- Scannable: Passed，原则要求稳定标题、筛选、表格、状态标签和行操作。
- Plugin-first: Passed，原则把插件页面、风险、权限和生命周期纳入同一视觉系统。
- No marketing style: Passed，原则明确不做营销页、展示型 hero 或说明文案替代真实控件。
