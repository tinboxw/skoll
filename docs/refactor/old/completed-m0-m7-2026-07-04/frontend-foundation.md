# Skoll 前端基础规范

> 合并范围: FE0-FE4 前端体验、视觉系统、架构规范、核心页面验收、插件与开发者门户体验。  
> 原始材料: 已归档到 `docs/archive/refactor-2026-06-19/`。

## 目标

Skoll Admin 的前端目标是优秀、漂亮、稳定、可扫描、可持续扩展。它是后台工作台，不做营销页式布局，不用装饰性渐变和大块 hero 叙事，不接受只有静态 UI、没有真实状态和权限约束的页面。

## 视觉与交互原则

1. 页面以信息效率为优先，标题、工具栏、筛选、表格、详情抽屉保持稳定结构。
2. 卡片只用于重复对象、模态框和真实工具容器，页面区域不要做卡片套卡片。
3. 表格列宽、操作区、状态标签、批量动作必须稳定，避免 hover 或动态内容导致布局跳动。
4. 表单、抽屉和弹窗必须包含校验、保存中、错误、确认和取消路径。
5. loading、empty、error、no-permission、success、failed 使用统一状态组件。
6. 窄屏必须无重叠、无按钮溢出；表格需要有降级策略。

## 前端架构边界

| 边界 | 规则 |
| --- | --- |
| API client | 统一请求、响应、错误、分页、导出封装，不在页面内散写协议细节 |
| Pinia store | 统一 loading、error、data、retry、refresh 模式 |
| Router/permission | 菜单、路由、按钮、插件权限同源，不做页面内临时绕过 |
| SchemaForm | 插件配置、系统设置、生成器表单复用同一表单边界 |
| Confirm action | 删除、禁用、回滚、发布等危险动作使用统一确认 helper |
| Error display | 后端错误不得被吞掉，也不得显示成假成功 |
| Export/download | 导出必须带当前筛选条件，失败可见 |

## 核心页面验收要求

| 页面 | 必须覆盖 |
| --- | --- |
| Dashboard | 系统状态、插件状态、风险项、快捷入口 |
| User | 筛选、批量、编辑、角色分配、组织归属状态 |
| Role | 角色列表、授权入口、关联用户、危险动作 |
| Permission | 权限矩阵、筛选、保存反馈、管理权限态 |
| Menu | 树表、排序、显隐、权限字段、保存确认 |
| Plugin | 状态、风险、权限、配置、访问、生命周期动作 |
| Audit | tab、筛选、详情、导出、风险标签、trace |
| Setting | SchemaForm、分组、敏感项、保存反馈、审计提示 |

每个页面至少记录正常、加载、空、错误、无权限、保存中、窄屏和关键命令结果。

## 插件与开发者门户

插件门户必须让高风险动作可读、可确认、可追踪:

| 场景 | 要求 |
| --- | --- |
| 插件列表 | enabled、risk、signature、version、health、actions 可扫描 |
| 详情抽屉 | 权限、菜单、配置、资产、日志、发布状态分区清楚 |
| 安装预检 | 权限 diff、菜单 diff、风险、签名、迁移影响清楚 |
| 风险报告 | 风险等级、因子、阻断原因、审计线索可读 |
| Dev Portal | 发布任务状态、步骤、日志、失败原因、重试、回滚清楚 |
| 重面板 | 日志、风险、发布历史按需加载，不阻塞首屏 |

## 验收命令

```powershell
cd web
npm run typecheck
npm run build
```

页面级验收还需要记录浏览器检查结论。浏览器工具不可用时，应明确记录阻塞原因和重试条件。
